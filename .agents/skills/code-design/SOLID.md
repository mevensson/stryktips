# SOLID

The five principles, kept short.

- **S — Single Responsibility** — a function/class/module changes for one reason only.
- **O — Open/Closed** — add behaviour by extending (composition/dispatch), not by editing existing code.
- **I — Interface Segregation** — no client depends on what it doesn't use; prefer narrow interfaces over wide ones.
- **L — Liskov Substitution** — a subclass substitutes for its base wherever the base is used, without breaking.
- **D — Dependency Inversion** — depend on abstractions, not concretions; inject dependencies.
